## 系统架构概览

```
┌──────────────────────────────────────────────────┐
│                  模块门户 (/portal)                │
│  登录后用户看到的第一个页面，以卡片形式展示所有     │
│  自己有权限访问的功能模块                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│  │ 系统管理  │  │ 支付管理  │  │ 订单管理  │  ...   │
│  └──────────┘  └──────────┘  └──────────┘        │
└──────────────────────────────────────────────────┘
        │               │              │
    点击卡片         点击卡片        点击卡片
        ▼               ▼              ▼
  进入子系统       进入子系统      进入子系统
```

**核心关系链**：

```
用户 (User) ──多对多──▶ 角色 (Role)
                             │
                 ┌───────────┼───────────┐
                 ▼                       ▼
          模块 (Module)           权限 (Permission)
         "能进哪个系统"         "能做什么操作"
```

- **模块 (Module)**：控制用户能看到门户中的哪些卡片，即"能进入哪些子系统"
- **权限 (Permission)**：控制用户在子系统内能执行哪些操作（resource:action）
- **角色 (Role)**：模块和权限的集合，是分配给用户的最小单位

## 核心概念

### 模块 (Module)

| 字段 | 说明 | 示例 |
|------|------|------|
| name | 模块名称，显示在门户卡片上 | `支付管理` |
| code | 唯一编码，用于路由识别 | `payment` |
| icon | Element UI 图标类名 | `el-icon-s-order` |
| description | 模块描述，显示在卡片副标题 | `支付订单管理与退款` |
| sort | 排序号，越小越靠前 | `2` |
| url | 外部模块入口地址（可选） | `http://localhost:8090` |
| status | 启用/禁用 | `1` |

> **url 字段的作用**：如果模块有外部地址，点击卡片会跳转到 `/module/:code`，用 iframe 加载外部系统。留空则使用内置路由（如 RBAC 自己的 `/dashboard`）。

### 权限 (Permission)

| 字段 | 说明 | 示例 |
|------|------|------|
| name | 权限名称 | `查看支付订单` |
| resource | 资源标识 | `payment` |
| action | 操作类型 | `read` |
| module_id | 所属模块 | `2` (支付模块) |

**常见操作类型**：`read`(读)、`create`(创建)、`update`(更新)、`delete`(删除)、`manage`(管理)、`publish`(发布)、`*`(全部)

> **通配符 `*:*`**：超级管理员权限，拥有所有资源的所有操作，且自动看到门户中所有启用模块。

### 角色 (Role)

角色同时绑定**模块**和**权限**：

- **分配模块** → 用户获得该模块的门户卡片入口
- **分配权限** → 用户获得该模块内的具体操作能力

> 两者可以独立分配。例如：只分配模块不分配权限 = 能看到卡片但进去后无法操作；只分配权限不分配模块 = 有能力但门户看不到入口。

### 用户 (User)

用户通过**分配角色**获取模块和权限。一个用户可以有多个角色，权限取并集。

## 快速开始：给用户分配模块权限

以新建用户 **李四**、分配 **支付模块** 为例。

### 场景一：只让用户能看到模块（不给操作权限）

```
步骤 1: 角色管理 → 新增角色 "支付访客"
步骤 2: 角色管理 → 点击 "支付访客" 的 [分配模块] → 勾选「支付模块」→ 确定
步骤 3: 用户管理 → 新建用户 "李四" → 点击 [分配角色] → 勾选「支付访客」
```

> ✅ 李四登录后，门户显示"支付模块"卡片，点击可进入。

### 场景二：给用户模块入口 + 具体操作权限

```
步骤 1: 权限管理 → 新建权限 "查看支付" (resource: payment, action: read, 模块: 支付模块)
                        新建权限 "创建支付" (resource: payment, action: create, 模块: 支付模块)
步骤 2: 角色管理 → 新建角色 "支付操作员"
步骤 3: 角色管理 → 点击 [分配模块] → 勾选「支付模块」
步骤 4: 角色管理 → 点击 [分配权限] → 勾选「查看支付」「创建支付」
步骤 5: 用户管理 → 新建用户 "李四" → 分配角色「支付操作员」
```

> ✅ 李四登录后看到支付模块卡片，进入后可以查看和创建支付，但不能退款。

### 场景三：给已有用户追加新模块

```
步骤 1: 角色管理 → 找到用户已有的角色（或新建）
步骤 2: 点击 [分配模块] → 追加勾选新模块 → 确定
        点击 [分配权限] → 追加勾选新模块的权限 → 确定
步骤 3: 无需重新分配用户（角色变更自动生效）
```

## 详细操作指南

### 模块管理

**路径**：侧边栏 → 模块管理

#### 新建模块

1. 点击「新增模块」按钮
2. 填写表单：

| 字段 | 必填 | 说明 |
|------|------|------|
| 模块名称 | ✅ | 门户卡片标题，如"支付管理" |
| 模块编码 | ✅ | 唯一标识，小写字母开头，如 `payment` |
| 图标 | 否 | Element UI 图标类名，如 `el-icon-s-order` |
| 描述 | 否 | 卡片副标题 |
| 排序 | 否 | 数字越小越靠前，默认 0 |
| 入口地址 | 否 | 外部模块的 URL，如 `http://localhost:8090`。**留空使用内置路由** |

3. 点击「确定」

#### 内置模块 vs 外部模块

| 类型 | url 字段 | 点击行为 |
|------|---------|---------|
| 内置 (RBAC) | 空 | 跳转 `/dashboard`（RBAC 子系统） |
| 外部系统 | `http://xxx` | 跳转 `/module/:code`（iframe 加载） |

#### 编辑 / 删除

- **编辑**：可修改所有字段，包括启用/禁用
- **删除**：仅当模块下无关联权限时才能删除

---

### 权限管理

**路径**：侧边栏 → 权限管理

#### 新建权限

1. 点击「新增权限」
2. 填写：

| 字段 | 必填 | 说明 |
|------|------|------|
| 权限名称 | ✅ | 如"查看支付订单" |
| 资源 (resource) | ✅ | 资源标识，如 `payment` |
| 操作 (action) | ✅ | 下拉选择：read/create/update/delete/manage/publish/* |
| 描述 | 否 | 权限用途说明 |
| 所属模块 | 否 | 下拉选择模块（选了模块后该权限自动归入对应模块） |

3. 点击「确定」

> **建议**：创建权限时尽量指定所属模块，这样通过权限链路也能正确推导出模块可见性。

---

### 角色管理

**路径**：侧边栏 → 角色管理

角色管理是**最核心的操作页**，包含三个功能：

#### 1. 新建 / 编辑角色

点击「新增角色」或「编辑」，填写角色名称和描述。

#### 2. 分配模块（控制用户能看到哪些门户卡片）

1. 点击角色的「分配模块」
2. 左侧为可选模块，右侧为已分配模块
3. 勾选后点击中间的箭头移动
4. 点击「确定」

> 用户获得该角色后，门户将显示该角色关联的所有模块卡片。

#### 3. 分配权限（控制用户能执行哪些操作）

1. 点击角色的「分配权限」
2. 左侧为可选权限，右侧为已分配权限
3. 使用穿梭框选择，点击「确定」

> 权限格式：`权限名称 (resource:action)`，如 `查看支付 (payment:read)`

---

### 用户管理

**路径**：侧边栏 → 用户管理

#### 新建用户

1. 点击「新增用户」
2. 填写用户名、密码、邮箱
3. 点击「确定」

#### 为用户分配角色

1. 点击用户的「分配角色」
2. 通过穿梭框选择角色
3. 点击「确定」

> 用户获得的模块 = 所有角色的模块取并集
> 用户获得的权限 = 所有角色的权限取并集

#### 修改密码 / 禁用用户

- **修改密码**：点击「改密」，输入旧密码和新密码
- **禁用用户**：编辑用户，将状态改为禁用

## 外部模块集成

### 架构说明

RBAC 系统作为**统一入口门户**，外部业务系统以模块形式注册。用户通过门户卡片进入各子系统。

```
用户登录 → 门户（/portal）
              │
              ├─ 点击「系统管理」→ RBAC 内部路由 /dashboard
              │
              └─ 点击「支付管理」→ iframe 加载 http://支付系统地址?rbac_token=xxx
```

### 接入步骤

#### 1. 在 RBAC 注册模块

模块管理 → 新增模块，填写入口地址为外部系统的 URL。

#### 2. 创建权限

权限管理 → 新建该模块对应的操作权限（如 `payment:read`）。

#### 3. 创建角色并绑定

角色管理 → 新建角色 → 分配模块 + 分配权限。

#### 4. 分配角色给用户

用户管理 → 给目标用户分配角色。

#### 5. 外部系统接收 Token

**方式一：URL 参数（推荐）**

```
外部系统 URL: http://localhost:8090?rbac_token=eyJhbGciOi...
```

外部系统前端从 URL 读取 token：

```javascript
const params = new URLSearchParams(location.search)
const token = params.get('rbac_token')
if (token) {
  localStorage.setItem('token', token)
  history.replaceState(null, '', location.pathname) // 清除 URL 中的 token
}
```

**方式二：postMessage**

```javascript
window.addEventListener('message', (event) => {
  if (event.data?.type === 'RBAC_TOKEN') {
    localStorage.setItem('token', event.data.token)
  }
})
```

#### 6. 外部系统后端鉴权

外部系统后端收到请求后，调用 RBAC introspect 接口验证：

```bash
curl -X POST http://<rbac-host>/api/v1/auth/introspect \
  -H "Content-Type: application/json" \
  -d '{
    "token": "<用户token>",
    "resource": "payment",
    "action": "refund"
  }'
```

返回示例：
```json
{ "code": 0, "data": { "active": true, "user_id": 3, "username": "lisi" } }
```

如果 `active` 为 `false`，说明 Token 无效或用户无此权限。

### Nginx 部署建议

```nginx
# RBAC 主站
server {
    listen 80;
    server_name admin.example.com;
    location / {
        root /opt/api-rbac/web/dist;
        try_files $uri /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8087;
    }
}

# 支付系统（独立部署，通过 iframe 集成）
server {
    listen 80;
    server_name payment.example.com;
    location / {
        root /opt/payment-web/dist;
        try_files $uri /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8091;
    }
}
```

模块入口地址配置为 `http://payment.example.com`。

## 常见场景示例

### 场景 1：新业务系统上线

> 背景：上线了"数据分析"系统，需要给数据分析团队开通权限。

```
1. 模块管理 → 新建模块「数据分析」(code: analytics, url: http://analytics:8090)
2. 权限管理 → 新建权限:
   - analytics:read  (查看报表)
   - analytics:export (导出报表)
3. 角色管理 → 新建角色「数据分析师」
   → [分配模块] 勾选「数据分析」
   → [分配权限] 勾选 analytics:read, analytics:export
4. 用户管理 → 给数据分析团队的用户分配「数据分析师」角色
```

### 场景 2：给不同用户分配同一模块的不同操作权限

> 背景：支付模块需要区分"操作员"和"审核员"。

```
角色: 支付操作员          角色: 支付审核员
├── 模块: 支付管理        ├── 模块: 支付管理
├── 权限: payment:read    ├── 权限: payment:read
├── 权限: payment:create  ├── 权限: payment:audit
                           └── 权限: payment:refund

用户A → 支付操作员 → 可查看+创建支付，不能审核退款
用户B → 支付审核员 → 可查看+审核+退款，不能创建支付
用户C → 两个角色都分配 → 拥有全部权限
```

### 场景 3：用户只能看某个模块但暂不操作

> 背景：新人入职，先熟悉系统，暂时不给操作权限。

```
1. 角色管理 → 新建角色「实习岗」
2. [分配模块] 勾选需要访问的模块
3. [分配权限] 不分配任何权限（或只分配 read 类权限）
4. 用户管理 → 给新人分配「实习岗」
```

### 场景 4：禁用某个模块

> 背景：某系统维护中，需要暂时对所有用户隐藏。

```
模块管理 → 编辑模块 → 状态改为「禁用」→ 确定
```

> 禁用后所有用户的门户中该模块卡片消失（超管除外，超管始终看到所有启用模块）。

## API 参考

### 模块相关

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/v1/auth/modules` | 登录即可 | 获取当前用户可见模块列表 |
| GET | `/api/v1/modules` | `module:read` | 模块列表（分页） |
| GET | `/api/v1/modules/:id` | `module:read` | 模块详情 |
| POST | `/api/v1/modules` | `module:create` | 创建模块 |
| PUT | `/api/v1/modules/:id` | `module:update` | 更新模块 |
| DELETE | `/api/v1/modules/:id` | `module:delete` | 删除模块 |

### 角色-模块关联

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/api/v1/roles/:id/modules` | `role:update` | 为角色分配模块（覆盖式） |
| DELETE | `/api/v1/roles/:id/modules/:modId` | `role:update` | 移除角色的某个模块 |

### 角色-权限关联

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/api/v1/roles/:id/permissions` | `role:update` | 为角色分配权限（覆盖式） |
| DELETE | `/api/v1/roles/:id/permissions/:permId` | `role:update` | 移除角色的某个权限 |

### 用户-角色关联

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/api/v1/users/:id/roles` | `user:update` | 为用户分配角色（覆盖式） |
| DELETE | `/api/v1/users/:id/roles/:roleId` | `user:update` | 移除用户的某个角色 |

---

> 更多 API 详见 Swagger 文档：启动服务后访问 `http://localhost:8087/swagger/index.html`
